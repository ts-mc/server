# 2026-10-24 — session fix log

Fixes for the bugs reported in the 2026-10-24 playtest (`latest.log`, chat with
Itz_sitian). All changes are config/data-level; nothing in `.archive` was touched.

## 1. "No permission" on store / vote / join / leave / quickjoin / party accept

**Root cause:** the BlueArcade3 (TheySix Events core) jar checks the legacy
`bluearcade.*` permission tree, but the LuckPerms H2 database only provisioned
`theysixevents.*` nodes on the `default` group. Mihai hand-granted the nodes
in-game during the session, but those grants were lost with the session.

**Fix:** 18 `bluearcade.*` nodes added to the `default` group directly in
`plugins/LuckPerms/luckperms-h2-v2.mv.db`:

```
bluearcade.join, .quickjoin, .leave, .vote, .votes, .store,
bluearcade.party, .party.create, .party.invite, .party.accept,
.party.deny, .party.leave, .party.list,
bluearcade.achievements, .stats, .level, .top, .credits
```

Verified via H2 query after patch (count = 18). A backup of the pre-patch DB is
at `/tmp/lp_repo_backup/`. No restart needed beyond the next boot.

## 2. "Economy Commands" help spam (9x) on /ba leave

**Root cause:** `plugins/BlueArcade3/rewards.yml` paid out money rewards with
`excellenteconomy give money ...` — but ExcellentEconomy's `give` subcommand is
**not standalone** (`give.Standalone.Enabled: false` in its commands.yml); it
lives under the currency root. Every payout dispatched an unknown command, so
the plugin printed its full help menu — one per reward line (9 payouts when the
arena emptied).

**Fix:** all eight payout lines changed to the correct root form:
`excellenteconomy money give {player} <amount> -s` (currency name first, then
the `give` child). The `-s` silent flag is supported (verified in the
GiveCommand bytecode).

## 3. PvP sword leaking into arenas / "cannot exit pvp mode"

**Root cause:** HubPVP's `disabled-worlds` only listed `spawn, lobby` — the
hub world is actually `world`, and the PG-01…PG-06 arena worlds were absent.
So the PvP sword stayed active inside minigame arenas, its activate/deactivate
broadcasts fired during games, and the sword could not be exited.

**Fix:** `plugins/HubPVP/config.yml` `disabled-worlds` now lists
`world, world_nether, world_the_end, spawn, lobby, PG-01 … PG-06`.
HubPVP now only ever runs in the hub.

Also repaired the same config file, which had the word "pvp" stripped from
several keys (bad prior edit): `block--when-disabled` → `block-pvp-when-disabled`,
`prevent--disable` → `prevent-pvp-disable`, message keys `-enabled`, `-disabled`,
`-already-enabled`, `-not-enabled`, `-disabled-world`, `-blocked` → proper
`pvp-*` names, and the `&§` mojibake in the activation broadcasts replaced with
the intended `§x§e§f§1§a§1§8` color code.

**Still open (jar bug, config can't fix):** the chest open/close duplication
trick on the locked PvP sword. The jar's click handlers only guard the player's
own inventory; chest/number-key swaps slip through. Needs a HubPVP jar patch
(add `InventoryOpenEvent`/`InventoryClickEvent` cancellation for chest views).

## 4. Stuck "winner's" tag

DeluxeTags `userdata/player_tags.yml` is empty (`{}`), so the stuck tag is
**not** DeluxeTags — it is the BlueArcade3 core's own team/tab tag that is not
cleared when the game ends (Mihai noted it only happens on OPs; it follows the
player back to the hub). Config exposes `tab_list_team_prefix` but no winner-tag
clear setting.

**Workaround available in game:** `/lp user <name> meta clear` is unrelated —
the tag is a scoreboard team prefix, so it clears on relog. A real fix needs a
core-jar patch in the `TeamSession` teardown path. Documented here for the
rebrand pass.

## 5. "No block data available for region 'game.floor' in arena 1/block_party"

**Root cause:** the arena `game.json` files in the repo tree were 0-byte
casualties (same corruption class as the 2026-09-20 fix log). The
`.archive` sync carries the real data, so they were restored.

**Fix:** `plugins/BlueArcade3/data/arenas/` replaced wholesale with the
`.archive` copy. The block_party game.json now parses and carries its floor
regions.

**Still open:** the archive has **no** regeneration snapshot `.bin` for
block_party — the snapshot was never captured. After the next boot, run the
block_party arena setup once (`/baa` region capture) to write the snapshot;
until then the plugin will still log that warning but the game runs.

## 6. Knockback minigame notes

Invisible circular barrier ("tf is this circle / i cant hit u in") and stacking
KB sticks are arena/jar behavior, not config. Documented in
`plugins/BlueArcade3/modules/knockback/settings.yml` comments with the in-game
steps to check (re-run dynamic-bounds setup; clear floor drops between rounds).
"kb without pvp" is expected: the module only applies velocity.
