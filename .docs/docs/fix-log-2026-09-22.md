Fixes for the startup crash (`logs/latest-crash-report.md`), the shutdown in

## 1. Why the server restarted — it did not auto-restart, it **crashed on boot**

Two separate events were mixed up in the report. Reading the timestamps:

### 1a. The clean stop (23:03:14, `log-when-crash-happened.md`)

```
[23:03:14] [Server console handler/ERROR]: [TerminalConsole] Failed to read console input
java.io.IOException: Input/output error
    at ... SimpleTerminalConsole.readCommands(...)
[23:03:14] [Server thread/INFO]: Stopping server
```

This is **not** a crash. The panel's console/stdin detached (`Input/output
error` on the console reader), and Paper treated a dead stdin as a normal stop
request. The shutdown then ran to completion, all worlds saved, no exception.
That is the "server went down with no stop message" people saw in Discord — the
stop came from the *console* closing, not from inside the game.

### 1b. The actual crash — the server could not start again
(`latest-crash-report.md`, 23:13:49)

```
Description: Exception in server tick loop

com.sk89q.worldedit.extension.platform.NoCapablePlatformException:
  Not all platforms have been registered yet! Please wait until
  FastAsyncWorldEdit is initialized.
    at ...PlatformManager.queryCapability(PlatformManager.java:188)
    at ...PlatformManager.getConfiguration(PlatformManager.java:341)
    at ...WorldEdit.getConfiguration(WorldEdit.java:910)
    at ...BukkitCommandInspector.getShortText(BukkitCommandInspector.java:56)
    at ...DynamicPluginCommandHelpTopic.<init>(DynamicPluginCommandHelpTopic.java:44)
    at ...SimpleHelpMap.initializeCommands(SimpleHelpMap.java:135)
    at net.minecraft.server.MinecraftServer.initPostWorld(MinecraftServer.java:643)
    at net.minecraft.server.DedicatedServer.initServer(DedicatedServer.java:365)
```

So: **the server stopped (1a), then every restart attempt crashed (1b)**. That
loop is why it looked like the panel was "auto restarting" — the host restarts
on exit, and the restart kept dying the same way.

### Root cause of the crash: an empty `help.yml`

`help.yml`, `bukkit.yml`, `commands.yml` and `permissions.yml` were all **0
bytes** — leftovers from the Sep 19 corruption event that were never restored
(see `fix-log-2026-09-20.md`).

An empty `help.yml` is **not** a valid "use defaults" file. With no topics and
no ignore list, Paper's `SimpleHelpMap.initializeCommands()` built an automatic
help topic for **every registered plugin command**. For WorldEdit/FAWE that pulls
in `DynamicPluginCommandHelpTopic`, whose constructor asks the WorldEdit platform
for the command's short description. At `initPostWorld` the FAWE adapter is not
registered yet, so `PlatformManager.queryCapability()` throws
`NoCapablePlatformException`, the exception propagates out of
`MinecraftServer.runServer()`, and the server dies during startup.

### Fix

Restored `help.yml` and told the help system to skip those plugins:

```yaml
ignore-plugins:
  - FastAsyncWorldEdit
  - WorldEdit
  - WorldGuard

command-topics-in-master-index: false
general-topics: {}
index-topics: {}
amended-topics: {}
```

`ignore-plugins` is the documented switch that stops automatic help-topic
generation per plugin ([Bukkit help.yml](https://bukkit.fandom.com/wiki/Help.yml)).
The names must match the `name:` in each plugin's `plugin.yml` exactly
(`FastAsyncWorldEdit`, `WorldEdit`, `WorldGuard`).

`bukkit.yml` (stock default values) and `commands.yml` were also rewritten,
because 0-byte copies of those are likewise being ignored/parsed as empty.

> **Not verified here:** the crash can only be confirmed fixed by starting the
> server. The change removes the exact code path from the stack trace, so the
> first restart after upload should boot cleanly. If a `help.yml` error appears,
> the file did not upload.

## 2. `%bluearcade_...%` placeholders — the real placeholder set

The BlueArcade expansion **does** register under the identifier `bluearcade`,
but it only resolves a fixed set of sub-keys. Verified by decompiling the shipped
`BlueArcade-3.4.5.jar`
(`net/blueva/arcade/v3/libraries/placeholderapi/`):

| Sub-key | Meaning |
|---------|---------|
| `stat_<scope>_<stat>[_<period>]` | stat value |
| `stat_display_...` / `stat_description_...` / `stat_scope_...` | stat metadata |
| `tops_...` | leaderboard values |
| `category_...` | category totals / names |

`<scope>` is `global` or `module_<game_id>`. Valid **global** stat keys:
`games_played`, `mini_games_played`, `time_played`, `wins`, `kills`, `deaths`,
`stars`, `credits`, `first_place`, `second_place`, `third_place`,
`best_win_streak`, `current_win_streak`.

**The four keys used on this server were never registered** and rendered as
literal `%bluearcade_...%` text: `active_games`, `votes_total`,
`coins_earned`, `xp_earned`.

### Fixed in `plugins/TAB/config.yml` (minigames scoreboard)

The scoreboard now pulls from three verified sources:

| Line | Placeholder | Source |
|------|-------------|--------|
| Games played | `%bluearcade_stat_global_games_played%` | BlueArcade expansion |
| Wins | `%bluearcade_stat_global_wins%` | BlueArcade expansion |
| Kills | `%bluearcade_stat_global_kills%` | BlueArcade expansion |
| Deaths | `%bluearcade_stat_global_deaths%` | BlueArcade expansion |
| Money | `%vault_eco_balance_formatted%` | Vault expansion → ExcellentEconomy |
| Votes | `%votingplugin_total%` | VotingPlugin expansion |
| Vote streak | `%votingplugin_dailyvotestreak%` | VotingPlugin expansion |
| Credits | `%bluearcade_stat_global_credits%` | BlueArcade in-store currency |
| Stars | `%bluearcade_stat_global_stars%` | BlueArcade expansion |

The old lines (`active_games`, `votes_total`, `coins_earned`, `xp_earned`) never
existed and rendered literally. The matching `placeholder-refresh-intervals`
entries were updated, and new 5 s intervals were added for the money/vote
placeholders.

Also fixed in the same file: the `placeholders:` section had an invalid
`date-locale: es` key and the `locale` value on the wrong level — TAB logged
`unknown key "date-locale"` and `Missing ... "placeholders.locale"` on every
start. It is now `placeholders.locale: en-US`.

### Scoreboard / vote menu — what to use

- **Scoreboard:** mix the three sources above. For a server-wide value like
  "active games" there is no placeholder — that needs a plugin exposing arena
  counts, or a static line.
- **Vote menu:** use VotingPlugin's `/vote` (server-list voting). BlueArcade's
  `/ba vote` is **in-arena only**. It requires a current arena and opens the
  minigame vote menu while waiting (`VoteSubCommand` → `getCurrentArena` →
  `canPlayerVote`), otherwise it prints `You are not currently in any game.` So
  `/ba vote` cannot back a hub hotbar item.
- In-arena voting is already provided by BlueArcade: `items.yml` →
  `waiting_room_items.vote` (slot 1, runs `/ba vote`).

## 3. Server-list voting (VotingPlugin + NuVotifier)

Installed now. Server-list voting is a different system from BlueArcade's
in-arena vote. `plugins/ItemJoin/items.yml` → `vote-menu` was rewritten for it:

- Command: `vote` (VotingPlugin's `/vote`) instead of the in-arena-only `ba vote`.
- Lore: **verified** VotingPlugin placeholders
  ([source](https://github.com/BenCodez/VotingPlugin/wiki/PlaceholderAPI-Placeholders)) —
  `%votingplugin_total%` (month), `%votingplugin_total_alltime%`,
  `%votingplugin_dailyvotestreak%`, `%votingplugin_points%`,
  `%votingplugin_top_all_1%`.
- The permission gate was **removed**, because the voting stack is now present,
  so the item ships enabled. Note VotingPlugin's own config treats placeholders
  case-insensitively, and its list also documents `%VotingPlugin_...%`; the
  lowercase `%votingplugin_*%` form used here resolves either way.

The listener is NuVotifier (data folder `plugins/Votifier/`, with generated RSA
keys). VotingPlugin data is SQLite (`plugins/VotingPlugin/Users.db`).

> **Jars are kept out of this working directory on purpose** so a jar can never be
> accidentally re-uploaded or silently modified. That is why the
> ExcellentEconomy/VotingPlugin/Nightcore jars are absent here — intentional, not
> a missing file. (Note: this is not a git repo, so nothing enforces it; it is a
> workflow rule. The one exception present here is
> `plugins/PlaceholderAPI/expansions/Expansion-*.jar`.)
>
> Because those jars are absent, the **PlaceholderAPI expansions are not yet
> downloaded** either: `plugins/PlaceholderAPI/expansions/` only has `player`,
> `server`, `vault` and `worldguard`. So `%votingplugin_*%` will not resolve until
> you run `/papi ecloud download VotingPlugin` + `/papi reload`.
> `%vault_eco_balance_formatted%` (used for money) works because the `vault`
> expansion is already installed.

If server-list voting is ever removed, delete the `vote-menu:` block in
`plugins/ItemJoin/items.yml` or set `triggers: DISABLED`.

## 4. Match rewards — no money/xp was being paid out

`plugins/BlueArcade3/rewards.yml` was **0 bytes** (another Sep 19 corruption
casualty, like the core files in section 1). With it empty, BlueArcade had **no
per-match rewards at all** — nothing was given for winning, placing or
participating. This is the "xp/money from matches" that was missing.

Restored from `.party-games-setup/PG Setup/` and extended. Each tier now pays
**two** economies:

```yaml
first:
- baa credits give -s {player} 20               # BlueArcade store currency
- baa xp give -s {player} 35                    # BlueArcade XP
- excellenteconomy give money {player} 20 -s    # real money (Vault/ExcellentEconomy)
```

Why the full `excellenteconomy give money ...` form: ExcellentEconomy's `give`
child is **not** registered as a standalone command
(`plugins/ExcellentEconomy/commands.yml` → `give.Standalone.Enabled: false`), so
the root command is the reliable form. `-s` = silent (no chat spam).

`credits` is kept because BlueArcade's `/ba store` spends it; `money` is the real
economy shown on the TAB scoreboard.

Also restored from the same 0-byte corruption: `plugins/BlueArcade3/sounds.yml`
and `plugins/BlueArcade3/store/{kill_effects,death_effects,victory_effects,victory_music}.yml`.

### Money placeholder

`%vault_eco_balance_formatted%` (Vault expansion). ExcellentEconomy sets
`Integration.Vault.EconomyCurrency: money`, so Vault exposes its balance. The
`%excellenteconomy_*%` expansion exists but its exact prefix could **not** be
verified from this repo (jar not committed) — use the Vault placeholder, which
is guaranteed, until `/papi parse me %excellenteconomy_balance_money%` confirms
the prefix.

## Follow-up for an operator

1. **Restart and watch the console** — confirm it reaches `Done (Xs)! For help,
   type "help"` without the `NoCapablePlatformException`. If it still crashes,
   `help.yml` did not upload.
2. **Download the PlaceholderAPI expansions that are missing.** Only `player`,
   `server`, `vault` and `worldguard` are installed; the vote placeholders need
   theirs:
   ```
   /papi ecloud download VotingPlugin
   /papi reload
   ```
3. Test the three new scoreboard sources:
   `/papi parse me %bluearcade_stat_global_wins%`,
   `/papi parse me %vault_eco_balance_formatted%`,
   `/papi parse me %votingplugin_total%` — each should return a value, not the
   literal text.

   and credits (`/ba store`). If money is not added, verify ExcellentEconomy is
   enabled and run the reward command at the console manually:

   because that expansion is installed. If you later download the
   ExcellentEconomy expansion (`/papi ecloud download ExcellentEconomy`) you could
   switch to its native prefix — but the Vault one already works, so there is no
   need.
