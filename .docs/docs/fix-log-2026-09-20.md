# TheySix Events — Fix Log (2026-09-20)

Fixes applied in response to the in-game bug report plus the errors in
`logs/latest.log`. No `.jar` was edited — every fix is configuration, data or
plugin-jar replacement with a correct upstream build.

## Root cause: files truncated to 0 bytes

A large number of config files, plugin libraries and caches were **0 bytes**.
They carry a common timestamp (`Sep 19 11:55`), i.e. one corruption/copy event.
This is what produced almost every symptom:

| 0-byte path | Consequence |
|---|---|
| `plugins/LuckPerms/libs/*.jar` | LuckPerms could not load `me.lucko.luckperms.lib.adventure.*` → plugin failed to enable |
| `plugins/BlueArcade3/libraries/*` | minigames core libs missing |
| `plugins/FancyGlow/libraries/*` | FancyGlow failed to enable |
| `plugins/FastAsyncWorldEdit/lang/strings.json` | FAWE `TranslationManager` NPE → FAWE failed to enable |
| `plugins/Essentials/items.json` | Essentials threw `Not a JSON Object: null` → Essentials, EssentialsChat, EssentialsSpawn all failed |
| `plugins/FancyNpcs/version.yml` (stale `2.10.1-java21`) | NPC data treated as an old format |
| `plugins/SkinsRestorer/cache/*.mojangcache` | SkinsRestorer `MojangCacheFile.toCacheData()` NPE |
| `plugins/BlueArcade3/settings.yml`, `items.yml`, `rewards.yml`, `sounds.yml`, `data/global.json`, `data/signs.json` | minigames core ran with empty settings and no main lobby |
| `plugins/FancyNpcs/logs/*`, `.apollo/crashes/*` | logs/crash reports unusable |
| many menu/language files under `plugins/BlueArcade3/` | plugin features empty |

**Action taken:** deleted the 0-byte *library* stubs and *regenerable* config
files so each plugin re-extracts or re-downloads a valid copy; replaced the
0-byte `Essentials/items.json`, `FAWE/lang/strings.json` and the FancyNpcs /
SkinsRestorer caches the same way. The authored `BlueArcade3/settings.yml` etc.
values were not recoverable from this repo, so they now regenerate from the
plugin's bundled defaults — re-apply any custom tweaks in game (`/baa`).

## Reported in-game bugs

### 1. Ghost-dropping diamond armour crashes the server
HubPVP locks a full diamond armour set into the player's inventory and
save/restores it around PvP. On death the restore can leave a ghost armour
stack, and dropping it crashed the server.
**Fix:** `plugins/HubPVP/config.yml` — the equipment set is now a **single PvP
sword** (no armour), so there is no armour stack that can ghost or drop. The
kill-streak reward commands that handed out diamonds/emeralds were also removed.

### 2. Damage taken without PvP mode on
HubPVP's empty config fell back to defaults whose `disabled-worlds` was
`[spawn, lobby]` — but the hub world's **level name is `world`**, so it was not
protected.
**Fix:** `plugins/HubPVP/config.yml` → `disabled-worlds: [world, spawn, lobby]`
and `combat.block-pvp-when-disabled: true`. Hub damage now requires an explicit
PvP activation, and `world` (and any group named `spawn`/`lobby` via
LuckPerms) is covered. See `docs/luckperms-setup.md` for the matching group.

### 3. NPCs not working
`plugins/FancyNpcs/npcs.yml` was written by FancyNpcs **2.10.1** but 2.12.0 is
installed, and the data folder's `version.yml` still said `2.10.1-java21`. Worse,
every `variant: AUTO` NPC had **no skin `identifier`**, so FancyNpcs queried
Mojang with nothing and the NPCs rendered without skins.
**Fix:**
- `plugins/FancyNpcs/version.yml` rewritten to the 2.12.0 value.
- Added `skin.identifier` to every `variant: AUTO` NPC, using the player names
  recovered from the surviving `plugins/FancyNpcs/.data/skins/` cache. The
  original per-NPC skin assignment was lost with the truncated data, so the
  mapping was reconstructed; adjust in game with `/npc skin <npc> <player>` if
  a specific skin is wanted.

### 4. Players not in adventure mode
`server.properties` had `gamemode=survival` / `force-gamemode=false`, and the
plugin that was supposed to manage hub gamemode (DeluxeHub) was never installed.
**Fix:** `server.properties` → `gamemode=adventure`, `force-gamemode=true`.
`plugins/ItemJoin/config.yml` join command changed from `gamemode survival` to
`gamemode adventure` so it cannot undo the setting if re-enabled.

### 5. Cosmetic pouch not reset on death → permanent "1 item could not be delivered"
`plugins/ItemJoin/items.yml` had `items-Overwrite: false`. The lobby cosmetics
pouch (slot 8) is protected from death drops, so on respawn it was still in the
inventory and ItemJoin refused to re-deliver it, printing the failure message on
every respawn.
**Fix:** `plugins/ItemJoin/items.yml` → `items-Overwrite: true`.

## World naming for the Discord game-chat channel (2026-09-20, follow-up)

**Goal:** the Discord `game-chat` channel should show which world a player is
speaking from, with a readable name instead of `PG-01` / `world`.

### How the world name gets into Discord
`plugins/DiscordSRV/messages.yml` →
```
MinecraftChatToDiscordMessageFormat: "%worldalias% | %displayname% > %message%"
```
`%worldalias%` is resolved through DiscordSRV's world hook. With Multiverse-Core
4.x installed the hook is `MultiverseCoreV4Hook`, which calls
`MVWorldManager.getMVWorld(name).getAlias()`. If the world is **not registered in
Multiverse**, the call returns null and DiscordSRV falls back to the raw world
name. So the readable name has to be a **Multiverse alias**.

### Changes
1. **`plugins/Multiverse-Core/worlds.yml`** (was a 0-byte casualty) rewritten
   with a world entry and alias for each world:

   | World (level name) | Alias |
   |--------------------|-------|
   | `world` | `Hub` |
   | `PG-01` … `PG-06` | `1v1 Duels`, `2v2`, `5v5`, `5v5 Chaos`, `10v10`, `Free-For-All` |
   | `world_nether` | `Nether` |
   | `world_the_end` | `The End` |

   Entries also set `gameMode: ADVENTURE` (reinforcing the adventure-mode fix),
   `pvp` (off in the hub, on in arenas), `hidden: true` for arenas so they are
   not listed in `/mv list`, and `respawnWorld: world`.

2. **Arena folders renamed `world_01` … `world_06` → `PG-01` … `PG-06`.**
   Multiverse loads a world by looking for a folder named after the world, so
   with folder `world_01` and level name `PG-01` it could neither load the world
   nor attach the alias. Folder now equals level name equals the `"world": "PG-01"`
   value used in `arena.json` / `games/*.json`. Nothing in the plugin configs
   referenced the old folder names (only the docs and `.vscode/sftp.json`, both
   updated).

3. **`docs/setup-guide.md`, `plugins/Multiverse-Core/README.md`,
   `docs/ilm-handover.md`, `.vscode/sftp.json`** updated for the new folder names.

### Still needs a manual step
- **`world_lobby`** declares level name `world` (collides with the hub) and its
  `level.dat` is truncated (no `SpawnX/Y/Z`). It is not loaded and therefore has
  no alias. Repair its `level.dat` and rename the level name to `world_lobby` to
  put it in `worlds.yml`.
- **`world_the_end/level.dat`** is 0 bytes; the entry is in `worlds.yml` but
  Multiverse will skip it and log a warning until the dimension regenerates.
- Rename an alias any time in game with
  `/mv modify set alias <world> "<name>"`.

### Arena aliases vs. the recommended setup

The arena aliases deliberately use the **format names** from the recommended
arena setups table in `docs/minigames-list.md`:

| World | Alias | Intended format |
|-------|-------|-----------------|
| `PG-01` | `1v1 Duels` | 1v1 |
| `PG-02` | `2v2` | 2v2 |
| `PG-03` | `5v5` | 5v5 |
| `PG-04` | `5v5 Chaos` | 5v5 chaos |
| `PG-05` | `10v10` | 10v10 |
| `PG-06` | `Free-For-All` | free-for-all, all 19 games |

Those formats are **not enforced by the shipped arena configs** — all six
arenas still run `mode: party` with all 19 games and `min/max 2/24`. The alias
describes the *intended* setup, so once the arenas are actually wired to those
formats with `/baa` the alias will match reality. Until then it is a label, not
a rule — rename with `/mv modify set alias <world> "<name>"` if you wire a
different layout.
